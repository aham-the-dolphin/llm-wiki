# Governance

This repository should be managed with clear ownership, review processes, versioning, and contribution guidelines.

## Ownership

The project owner is responsible for:

- defining the project vision and roadmap
- approving architecture and ADR decisions
- reviewing major changes to ingestion, validation, and reporting logic

## Review Process

All changes should be submitted via pull request and reviewed by at least one maintainer before merging. Review criteria include:

- correctness of new logic
- test coverage for new functionality
- documentation updates for new behavior
- compliance with repository style and linting

## Versioning

This project uses semantic versioning for releases. Changes should be categorized as:

- `major` for backwards-incompatible changes
- `minor` for new features
- `patch` for bug fixes and documentation only updates

## Contributions

Contributors should:

- open issues for new feature proposals or bug reports
- create focused pull requests with clear descriptions
- include tests for new functionality
- update documentation and ADRs when relevant

## Maintenance

Keep dependencies updated, maintain the `README.md` for developer onboarding, and ensure reports and templates remain aligned with the project schema.
